# 照片 EXIF 自动填充与定位服务修复

## 执行信息

- **任务类型**：新增功能 + Bug 修复
- **日期**：2026-07-18
- **目标**：上传含 EXIF 信息的照片时自动填充票根信息（地点、时间）；修复默认状态 IP 定位失效问题；地名按国内外使用中/英文

## 问题/需求描述

1. 上传照片时仅支持从文件名提取日期，无法读取照片真实的 EXIF 信息（拍摄时间、GPS 位置）。
2. 默认状态（未上传照片）地点恒为「北京市」：原 IP 定位服务 ipapi.co 免费接口已失效（返回付费提示文本而非 JSON），静默落入兜底值。
3. 用户补充规则：国外地名用英文（如 Singapore），国内地名用中文（如 武侯区）。

## 解决方案

### EXIF 解析（`useImageUpload.ts`）

- 新增依赖 `exifr`（浏览器端 EXIF 解析）。
- 拍摄时间：优先 `DateTimeOriginal`，兜底 `CreateDate` / `DateTime`，最终兜底原文件名日期提取。
- GPS 坐标：经 Nominatim（OSM）逆地理编码为地名，取 `city || town || county || village || state`；失败/超时（6s）则保持原地点。

### 上传结果应用（`HomeView.vue`）

- 合并 handleUpload / handleDrop 重复逻辑为 `applyUploadResult`。
- EXIF 填充 `date`、`location`，并同步 `code` 为拍摄日期 YYMMDD（保持票面日期与编号一致）。

### 默认 IP 定位修复（`useMockData.ts`）

- 定位服务由 ipapi.co 更换为 `ipwho.is`（免费、HTTPS、支持中文地名），加 6s 超时，失败兜底「北京市」不变。

### 国内外语言规则

- IP 定位与 EXIF 逆地理采用同一策略：先请求英文结果，`country_code` 为中国（`CN`/`cn`）时再追加一次中文请求；两次请求共用一个 6s 超时。

## 关键代码

```ts
// useImageUpload.ts — 逆地理编码（国内外语言规则）
const addr = await fetchAddr('en')
const zhAddr = addr?.country_code === 'cn' ? await fetchAddr('zh') : null
clearTimeout(timer)
return pickLocation(zhAddr) || pickLocation(addr)
```

```ts
// HomeView.vue — EXIF 填充并同步编号
const applyExifData = (exifData: Partial<TicketInfo>) => {
  if (exifData.date) {
    ticketInfo.value.date = exifData.date
    ticketInfo.value.code = exifData.date.slice(2).replaceAll('-', '')
  }
  if (exifData.location) ticketInfo.value.location = exifData.location
}
```

## 遇到的问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 默认地点恒为「北京市」 | ipapi.co 免费接口失效，返回付费提示导致 `response.json()` 抛错落入兜底 | 更换为 ipwho.is 并加超时控制 |
| 成都坐标逆地理得到「武侯区」而非「成都市」 | Nominatim 的 address 组件中 `city` 字段为区县级（OSM 中国区划数据未将地级市作为标准组件返回） | 保持区县级粒度（更精确，用户确认接受） |
| Playwright / Chrome DevTools MCP 浏览器实例被占用 | 另一会话持有浏览器 profile 锁 | 改用 `npm install --no-save puppeteer-core` 驱动本机 Chrome 完成 CDP 验收 |
