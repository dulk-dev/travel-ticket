## 背景

在技术栈选型阶段完成后，Git 提交过程中遇到了一个实际问题：Windows 环境下 `git commit -m` 命令含空格时解析失败。在解决这个问题的过程中，用户提出一个更深层的协作规范需求——如何系统性地沉淀 Agent 犯错的经验，避免后续 Agent 重复踩坑。

---

## 讨论过程

### 问题 1：Agent 犯错时如何系统性沉淀经验

- **讨论点**：Agent 在协作过程中犯错是常态，如何让错误变成可复用的约束规则？
- **方案对比**：
  - 方案 A：靠 Agent 自身的记忆系统，但记忆有冷却机制和遗忘风险
  - 方案 B：靠项目文档（如 AGENTS.md），新 Agent 接入时可直接阅读
- **最终决策**：选择方案 B，建立 **AGENTS.md** 作为 Agent 协作的约束手册。原因：
  - 文档是项目的一部分，不受 Agent 记忆冷却影响
  - 新 Agent 可以随时读取，无需依赖前任 Agent 的记忆传递
  - 错误模式一旦沉淀，所有后续 Agent 都能遵守

### 问题 2：AGENTS.md 的内容定位

- **讨论点**：AGENTS.md 应该记录什么？和阶段记录/执行记录的区别是什么？
- **最终决策**：
  - **阶段记录/执行记录**：记录项目本身的决策和实现（业务层面）
  - **AGENTS.md**：记录 Agent 协作过程中的工具使用陷阱和规避方案（协作层面）
  - 两者互补：阶段记录回答"项目做了什么"，AGENTS.md 回答"Agent 该怎么协作"

### 问题 3：沉淀的时机和格式

- **讨论点**：什么时候把错误写入 AGENTS.md？格式应该多长？
- **最终决策**：
  - **时机**：Agent 反复犯错或遇到非预期行为时，立即沉淀
  - **格式**：简短精炼，一句话描述现象 + 一句话给出解决方案（参考当前 AGENTS.md 的写法）
  - **原则**：不求完整，但求可执行——Agent 读到就能立刻规避

---

## 关键思路

1. **错误即资产**：Agent 犯错不是坏事，不沉淀才是浪费。每个错误都是后续 Agent 的避雷针。
2. **文档优先于记忆**：Agent 记忆有冷却和遗忘，项目文档永久存在。协作规范必须写在文档里。
3. **约束而非建议**：AGENTS.md 不是"最佳实践建议"，而是"必须遵守的约束"。Agent 读到就要执行。
4. **简短可执行**：一条经验控制在两句话以内，现象 + 方案，Agent 无需思考就能照做。
