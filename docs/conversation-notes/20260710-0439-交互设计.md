# 旅行票根 Web 应用 — 交互设计阶段记录

**日期**：2026-07-10  
**阶段**：交互与功能设计  
**参与者**：用户、Agent

---

## 背景

用户希望构建一个 Web 端应用，允许用户上传旅行照片，生成一张具有票根风格的纪念卡片，并支持下载保存。参考图展示了两种场景：白天海滩（连云港）和夜景城市（武汉），卡片由左侧照片取景区和右侧票根信息区组成。

## 讨论过程

### 问题 1：图片上传后的交互方式

- **讨论点**：用户上传照片后，如何调整照片在取景框内的显示区域？
- **方案对比**：
  - 仅支持简单缩放 vs 支持拖动+滚轮缩放
  - 缩放中心以取景框中心 vs 以鼠标位置为中心
  - 拖动是否允许完全移出取景框
- **最终决策**：
  - 支持鼠标拖动调整位置，限制不能完全移出取景框（至少保留 10% 内容）
  - 滚轮缩放以鼠标指针位置为中心，更符合直觉
  - 缩放范围：最小保证填满取景框，最大放大至原图 3~5 倍

### 问题 2：左侧取景框尺寸调整

- **讨论点**：取景框的横向/纵向调整是否影响整体卡片尺寸？
- **最终决策**：整体卡片尺寸固定，取景框调整仅改变图片在框内的裁剪区域和显示比例

### 问题 3：右侧票根信息的来源与编辑策略

- **讨论点**：地点、时间等信息从照片 EXIF 自动读取，缺失时如何处理？编号和随机码如何生成？
- **最终决策**：

| 字段 | 自动读取 | 无 EXIF 时 | 用户可编辑 |
|------|---------|-----------|-----------|
| 地点 | EXIF GPS | 留空待填 | 是，支持中英文 |
| 时间 | EXIF 拍摄时间 | 留空待填 | 是 |
| 编号 | — | 格式 `YYMMDD` | 是 |
| 随机码 | 基于照片特征生成固定短码 | 自动生成 | 是 |
| 条形码 | 纯装饰性，与编号对应 | 自动生成 | 否（跟随编号） |

### 问题 4：主题色提取与夜景处理

- **讨论点**：如何从照片提取主题色？夜景如何避免取到暗色调？背景板与票根区域的色差关系？
- **最终决策**：
  - 上传后自动提取主题色，同时提供候选色板供用户微调
  - 整体色系低饱和处理（原饱和度 30%~40%）
  - 夜景判定：整体亮度低 + 存在高亮区域时，取突出主题色而非暗色调
  - 背景板比票根区域更深，深浅关系自适应动态调整

### 问题 5：下载输出格式

- **讨论点**：支持哪些下载格式？渲染分辨率如何？
- **最终决策**：支持 PNG 和 JPG 两种格式，固定高分辨率渲染（2x 或 3x）

## 关键思路

1. **交互直觉优先**：滚轮缩放以鼠标位置为中心，拖动限制边界，都是为了让用户操作更符合直觉
2. **信息自动+手动结合**：EXIF 自动读取减少用户输入，但全部留空兜底保证灵活性
3. **色彩自适应**：夜景处理通过"亮度+高亮区域"联合判定，避免纯黑/灰色，提取旅行场景中的主题色彩
4. **固定尺寸策略**：卡片尺寸固定，取景框调整只改变裁剪，保证输出一致性

## 待确认事项

- [ ] 整体卡片的具体固定尺寸（如 1200×600 或 2:1 比例）
- [ ] 候选色板展示的数量和交互形式（如 4~6 个色块横向排列）
- [ ] 编号和随机码的字符集规则（如随机码是否仅大写字母+数字）
- [ ] 下载时的分辨率具体数值（2x 还是 3x）

## 预期结果

本次交互设计确认后，应用将具备清晰的用户操作流程：上传照片 → 自动提取信息/主题色 → 用户微调照片位置/信息/颜色 → 下载票根卡片。下一步可进入技术栈选型或 UI 视觉设计阶段。
