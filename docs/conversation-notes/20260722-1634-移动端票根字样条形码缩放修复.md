# 移动端票根字样与条形码缩放修复

- **日期**：2026-07-22
- **类型**：Bug 修复
- **目标**：修复移动端票根信息区文字和条形码相对于票根尺寸偏大（臃肿）的问题，使其与 PC 端保持一致的视觉比例

## 问题描述

移动端票根的文字字样（地点、日期、编号、随机码）和条形码在视觉上明显比 PC 端臃肿，占据了信息区过多的空间。PC 端票根显示比例协调，但同样的票根在移动端小屏幕上字样偏大、条形码更是占了近 1/3 高度。

## 分析思路（Duck 模式溯源）

从票根容器入口开始，逐节点追踪渲染流：

1. **票根容器宽度差异**：PC 端 ~700-900px → 高度 ~298-383px；移动端 ~343px → 高度 ~146px。高度缩至 PC 端的 38-49%。
2. **InfoArea baseFontSize 计算**：`Math.max(10, Math.round(height * 0.06))`。PC 端 `340*0.06=20px`（6.0%）；移动端 `146*0.06=8.76` 被 `max(10,...)` 抬至 10px（6.85%），比例失调。
3. **Barcode 固定高度**：容器 `h-12`（48px）+ JsBarcode `height: 36`，均为固定像素值。PC 端 `48/340=14.1%`；移动端 `48/146=32.9%`，占了近 1/3。

**根因定位**：
- baseFontSize 的 10px 下限在小票根场景下阻止了等比缩放
- Barcode 使用绝对像素尺寸，完全不随票根高度变化

## 解决方案

### 1. 降低 baseFontSize 下限（InfoArea.vue）

将 `Math.max(10, ...)` 改为 `Math.max(6, ...)`，让 `height * 0.06` 在移动端自然生效。

```js
// 修复前
baseFontSize.value = Math.max(10, Math.round(height * 0.06));

// 修复后
baseFontSize.value = Math.max(6, Math.round(height * 0.06));
```

### 2. Barcode 改为相对单位（Barcode/index.vue）

- 容器高度从固定 `h-12`（48px）改为 `2.4em`，跟随 InfoArea 的 baseFontSize 等比缩放
- JsBarcode 的 `height` 和 `width` 改为根据容器实际高度动态计算
- 新增 ResizeObserver 监听容器尺寸变化

```js
// 容器高度：2.4em（PC 端 ≈ 48px，移动端 ≈ 22px）
// JsBarcode 参数动态化
width: Math.max(0.8, h / 24),
height: Math.round(h * 0.75),
```

## 修复效果对比

| 指标 | PC 端 (h≈340px) | 移动端 修复前 | 移动端 修复后 |
|------|------|------|------|
| baseFontSize | 20px (6.0%) | 10px (6.85%) ⚠️ | 9px (6.0%) ✅ |
| 地点字号 | 40px (11.8%) | 20px (13.7%) ⚠️ | 18px (12.3%) ✅ |
| 条形码容器 | 48px (14.1%) | 48px (32.9%) ‼️ | ~22px (14.8%) ✅ |
