## 背景

在交互设计和 UI 原型设计完成后，本次讨论聚焦技术栈选型与项目架构设计。用户提出三个核心需求：
1. 尽可能组件化
2. 采用现代流行的技术栈
3. 方便扩展，以支持未来新增功能

此外，项目要求偏向离线应用，不对外进行网络访问，票根图片在浏览器端直接生成。

## 讨论过程

### 问题 1：前端框架选择

- **讨论点**：Vue 还是 React？
- **方案对比**：
  - Vue 3：用户主要使用，组件化直观，对新手友好
  - React：用户也可接受，生态丰富
- **最终决策**：选择 **Vue 3**，原因：用户熟悉度高，组件化设计直观，与项目团队技能匹配

### 问题 2：构建工具与样式方案

- **讨论点**：构建工具和 CSS 方案选择
- **方案对比**：
  - Vite vs Webpack：Vite 构建速度更快，配置更简洁
  - Tailwind CSS vs 传统 CSS：Tailwind 原子化类名，开发效率高
- **最终决策**：
  - 构建工具：**Vite**（速度快，Vue 3 官方推荐）
  - 样式方案：**Tailwind CSS**（原子化类名，与 Vite 集成简洁）
  - 类型系统：**TypeScript**（代码可靠性，Vue 3 官方支持）

### 问题 3：票根图片生成方案

- **讨论点**：在浏览器端直接生成票根图片，选择手写 Canvas 还是网页截图工具？
- **方案对比**：
  - 方案 A（手写 Canvas）：像素级控制，效果上限高，但代码量大
  - 方案 B（html2canvas）：网页效果直接映射为图片，CSS 样式自然保留，一致性最好
- **评估标准**：最终呈现效果为最高优先级，工作量不作为约束条件
- **最终决策**：选择 **html2canvas**（方案 B），原因：
  - 项目已完成精细的 UI 原型设计，网页效果即最终效果
  - 主题色提取、低饱和处理、背景板深浅关系等视觉要求用 CSS 实现最方便
  - html2canvas 能直接捕获这些效果，保真度最高
  - 时间应花在视觉调优上，而非重复造轮子

### 问题 4：条形码生成方案

- **讨论点**：票根右侧区域较窄，条形码如何美观呈现？
- **方案对比**：
  - 纯装饰性手绘条纹：简单，但缺乏真实感
  - jsbarcode 库生成后自定义样式：真实感强，可调整高度/间距/颜色适配窄区域
- **最终决策**：使用 **jsbarcode** 生成条形码，但**不直接显示原生样式**，而是通过 CSS 自定义样式（调整高度、间距、颜色）后再由 html2canvas 截图，兼顾真实感与美观性

### 问题 5：版本选择

- **讨论点**：各技术栈应使用哪个版本？
- **调研方式**：通过网络搜索查询当前最新稳定版本
- **最终决策**：

| 技术/库 | 版本 | 选择理由 |
|---------|------|----------|
| Vue | ^3.5.13 | 当前最新稳定版，性能优化完善 |
| Vite | ^6.2.1 | 构建速度极快，Vue 3 完美兼容 |
| TypeScript | ^5.7.x | Vue 3 官方推荐，类型支持完善 |
| Tailwind CSS | ^4.0.15 | 最新大版本，Vite 集成更简洁 |
| html2canvas | ^1.4.1 | 当前最新稳定版（原版已4年未更新，但功能稳定） |
| jsbarcode | ^3.12.3 | 最新稳定版，支持多种条形码格式 |

- **特别说明**：html2canvas 原版已长期未更新，如后续遇到兼容性问题，可切换到社区分支 `html2canvas-pro`

## 项目架构设计

### 目录结构

```
travel-ticket/
├── public/                       ← 静态资源
│   └── favicon.ico
├── src/                          ← 源代码
│   ├── assets/                   ← 图片、字体等素材
│   │   └── fonts/
│   ├── components/               ← 可复用组件
│   │   ├── TicketCard/           ← 票根卡片（核心）
│   │   │   ├── index.vue         ← 票根卡片主体
│   │   │   ├── PhotoArea.vue     ← 左侧照片区域
│   │   │   └── InfoArea.vue      ← 右侧信息区域
│   │   ├── UploadButton/         ← 上传按钮
│   │   ├── ColorPalette/         ← 候选色板
│   │   ├── InfoEditor/           ← 信息编辑面板
│   │   └── Barcode/              ← 条形码
│   ├── composables/              ← 可复用逻辑
│   │   ├── useImageUpload.ts     ← 图片上传
│   │   ├── usePhotoTransform.ts  ← 照片拖动/缩放
│   │   ├── useColorExtract.ts    ← 主题色提取
│   │   ├── useTicketExport.ts    ← 票根下载导出
│   │   └── useMockData.ts        ← Mock数据生成
│   ├── views/                    ← 页面级组件
│   │   └── HomeView.vue          ← 首页（左右/上下分栏）
│   ├── App.vue                   ← 应用根组件
│   └── main.ts                   ← 应用入口
├── index.html                    ← HTML模板
├── vite.config.ts                ← Vite配置
├── tailwind.config.js            ← Tailwind样式配置
├── tsconfig.json                 ← TypeScript配置
└── package.json                  ← 依赖清单
```

### 数据流向

```
用户上传照片
    ↓
PhotoArea 显示照片 + 触发颜色提取
    ↓
useColorExtract 提取主题色 → 更新背景色 + 生成候选色板
    ↓
InfoEditor 激活编辑状态 + 填充EXIF信息（或mock数据）
    ↓
用户微调（拖动照片/编辑字段/选择颜色）
    ↓
TicketCard 实时更新预览
    ↓
点击下载 → useTicketExport 用 html2canvas 生成图片
```

## 关键思路

1. **效果优先于效率**：技术选型以最终视觉保真度为首要标准，工作量不作为约束条件
2. **网页效果即最终效果**：html2canvas 将网页渲染结果直接转为图片，保证设计与输出一致性
3. **Vue 组合式函数复用逻辑**：useXxx 系列组合式函数将上传、变换、颜色提取、导出等逻辑抽离，组件只关注呈现
4. **渐进式激活设计**：未上传时组件处于禁用/预览状态，上传后逐步解锁，与交互设计阶段的全状态一致性原则呼应
