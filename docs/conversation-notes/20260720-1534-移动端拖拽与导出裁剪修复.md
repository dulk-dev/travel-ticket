# 移动端拖拽与导出裁剪修复

- **日期**：2026-07-20
- **类型**：Bug 修复
- **状态**：已完成

## 问题描述

移动端存在两个 bug：

1. **图片上传后无法拖动**：移动端触摸图片后无任何拖拽/缩放响应
2. **导出后文字被裁剪**：导出图片中地点文字（如 "SINGAPORE"）右侧末尾被截断

## 分析思路

### Bug 1：移动端无法拖动

使用橡皮鸭走查法（duck debugging），逐节点追踪触摸事件的数据流：

```
用户触摸图片 (touch)
    │
    ▼
PhotoArea.vue  <img @mousedown="onMouseDown">
    │ ⚠️ 只监听了 mousedown，没有 touchstart
    ▼
usePhotoTransform.ts → onMouseDown(e: MouseEvent)
    │ ⚠️ 只处理 Mouse* 事件
    ▼
window: mousemove / mouseup
    │ ⚠️ 没有 touchmove / touchend
    ▼
结果：移动端触摸事件完全不触发任何拖拽逻辑
```

**根因**：`usePhotoTransform` 只实现了 Mouse 系列事件，完全没有 Touch 系列事件支持。移动端提示"双指缩放 · 拖动调整位置"但实际无任何 touch gesture 处理。

### Bug 2：导出文字裁剪

走查导出流程中地点文字的渲染路径：

```
InfoArea.vue
    ▼
locationLines = ['SINGAPORE', '']  （单词不可拆分，只有一行）
    ▼
measureTextWidth (Canvas 测量)
    │ ⚠️ Canvas 测量与浏览器实际渲染存在精度差异
    ▼
locationScale 可能未触发缩放（测量值 ≤ 可用宽度）
    ▼
<div class="overflow-hidden w-full">
    │ ⚠️ overflow-hidden 裁掉了实际渲染中略微溢出的部分
    ▼
导出结果：最后一个字母 "E" 尾部被裁
```

**根因**：Canvas `measureText` 与浏览器实际渲染之间存在细微精度差异（字体度量、子像素渲染），当文字宽度刚好接近容器宽度时，`locationScale` 未触发缩放，而 `overflow-hidden` 将超出部分裁掉。

## 解决方案

### Bug 1

- `usePhotoTransform.ts`：新增 `onTouchStart` / `onTouchMove` / `onTouchEnd` 三个 touch 事件处理器
  - 单指拖拽：复用现有 `constrainTranslation` 约束逻辑 + 磁吸
  - 双指缩放（pinch-to-zoom）：记录初始双指距离和中心点，缩放时保持双指中心不动并跟随平移
  - 双指→单指切换：重新初始化单指拖拽起点，避免跳变
- `PhotoArea.vue`：`<img>` 绑定 `@touchstart.prevent`，`onMounted` 中注册 `window.touchmove`（`passive: false` 阻止页面滚动）和 `window.touchend`

### Bug 2

- `InfoArea.vue`：移除地点容器的 `overflow-hidden`（外层 TicketCard 已有 `overflow-hidden` 兜底，不会溢出票根边界）
- 给 Canvas 文字测量结果乘以 `1.02`（2% 安全边距），确保测量精度差异不会导致 `locationScale` 遗漏缩放

## 文件变更

| 文件路径 | 变更类型 | 说明 |
|----------|----------|------|
| `src/composables/usePhotoTransform.ts` | 修改 | 新增 touch 事件处理（单指拖拽 + 双指缩放） |
