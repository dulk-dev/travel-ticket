# 票根阴影与导出保真系列修复

- **日期**：2026-07-19
- **任务类型**：新增功能 + Bug 修复（含三项排查结论）
- **目标**：为票根增加贴近实物的整票阴影；系统性解决导出图片与预览不一致的问题（放大失真、视口依赖、导出闪跳）

## 一、整票阴影（新增功能）

### 问题

票根本体带 Tailwind `shadow-2xl`，但截图确认完全不可见：票根用
`mask-image: radial-gradient(...)` 切右侧半圆缺口，mask 绘制区默认限于
border-box，落在外部的 box-shadow 被整体裁掉。

### 方案

- 移除票根本体无效的 `shadow-2xl`，改在倾斜包装层（无 mask）加双层
  `filter: drop-shadow()`：近层接触阴影 `0 10px 16px rgba(0,0,0,.30)` +
  远层环境阴影 `0 28px 56px rgba(0,0,0,.32)`。
- drop-shadow 跟随 mask 后真实轮廓投影（圆角 + 缺口镂空均正确），
  hover 倾斜时随卡片做 3D 变换。
- 导出目标是票根元素而非包装层，导出图保持纯净无阴影。

## 二、导出放大失真（Bug 修复）

### 问题

用户导出图中照片与文字被整体放大、溢出裁切（"SINGAPORE" 裁成 "SINGA"）。

### 根因（双因叠加）

1. **烘焙值滞后**：字号（baseFontSize）、地点缩放（locationScale）、照片铺满
   尺寸（baseSize）都是 ResizeObserver 异步烘焙进内联样式的值；
   html2canvas 直接克隆 DOM 快照，烘焙值滞后会与当前布局混合产生"放大"。
   实验证实：把宽窗口烘焙值注入窄窗口票根，导出走样与用户图片完全一致。
2. **隐藏实例误导出**：桌面/移动两个 TicketCard 实例始终同时挂载，
   `downloadTicket` 无条件优先取桌面实例；移动端视口下其为 display:none，
   烘焙值失效，实测导出为 0 字节空白文件。

### 方案

- `downloadTicket` 按 `offsetWidth > 0` 选当前可见实例；
- 导出前 `prepareForExport()` 同步重算烘焙值并 `await nextTick()`，
  保证快照与当前布局一致。

## 三、色差排查（结论：非导出缺陷）

用户反馈导出图在 Windows 照片应用中偏浅偏黄。实测数据链：
预览截图 (206,119,58) = 导出文件 (207,119,58) = Chrome 复开 (207,119,58)，
WIC 色彩转换恒等。**导出文件颜色数据正确**，色差来自本机显示器多 ICC
Profile（EyeCare_D50/DCI_P3/Print_D50/sRGB_D65）下 Windows 照片应用与
Chrome 的色彩管理路径差异。无代码改动。

## 四、"修复后仍失真"排查（hunt，结论：陈旧客户端）

用户 16:54 再次导出仍走样。netstat 发现 localhost:5173 上有 **msedge.exe**
的 ESTABLISHED 连接——用户日常用 Edge；我的验证都在 MCP Chrome（当时
1440px 视口，不可能产出 1251px 导出）。其 Edge 标签页在修复发布时处于
后台/冻结，错过了 Vite HMR 更新（更新不重放、不重连刷新），持续运行旧代码。
**结论：用户侧硬刷新（Ctrl+Shift+R）即可**。无代码改动。

## 五、导出与窗口尺寸解耦（Bug 修复）

### 问题

用户观察：窗口大小影响导出效果。实测：830px 视口导出条形码占票高
**24.5%**，1440px 视口为 14.5%，分辨率 1251px vs 2400px。

### 根因

票根响应式布局（`width:100%`），而条形码固定 `h-12`（48px）、裁剪线固定
12px——固定 px 元素不随票根缩放。文字为纯比例缩放（票高 6%），一直正确。

### 方案演进

1. ~~导出时强制可视票根切到 900px~~ → 可行但导出瞬间票根闪跳，观感差；
2. **最终方案：常驻离屏导出专用实例**（`position:fixed; left:-10000px`，
   固定 900px，非 display:none）。它始终按 900px 布局，烘焙值天然为 900px
   状态；导出时只把用户在可视票根上的照片取景（缩放/平移）按铺满基准尺寸
   比例映射过去：

```ts
// PhotoArea.applyPhotoState：跨容器取景映射
transform.value = {
  scale: state.scale, // 缩放因子无量纲直接传递
  translateX: (state.translateX * baseSize.value.width) / state.baseWidth,
  translateY: (state.translateY * baseSize.value.height) / state.baseHeight,
}
```

可视票根全程不动 → 零闪跳；任何视口导出均为 2700x1149。

## 六、tilt 卡顿排查（结论：应用无缺陷）

用户反馈 3D 倾斜卡顿。探针实测：Vue 每帧组件更新合计 ~0.15ms；
离屏实例隐藏前后耗时一致（排除）；生产构建与 dev 一致（排除 devtools）；
布局/绘制/栅格占比极小；复测帧中位 12.6ms（约 80fps），用户确认已恢复。
推断为瞬态环境状态（多轮 HMR 累积 + 系统负载）。无代码改动。

## 遇到的问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| box-shadow 不可见 | mask-image 裁掉边界外阴影 | 阴影迁移到无 mask 的包装层 drop-shadow |
| 导出内容放大 | RO 烘焙值滞后 + 隐藏实例误导出 | 导出前同步重算 + 选可见实例 |
| 修复后仍失真 | 用户 Edge 标签页错过 HMR，运行旧代码 | 硬刷新（流程规范：改完代码刷新预览页） |
| 条形码窄视口占比失真 | 固定 48px 不随响应式票根缩放 | 固定 900px 设计宽度导出 |
| 900px 切换致闪跳 | 宽度切换施加在可视票根上 | 常驻离屏 900px 导出实例 + 取景映射 |
