# 票根信息区字体响应式自适应优化

## 执行信息

| 项目 | 内容 |
|------|------|
| **任务类型** | UI优化 / 技术复盘 |
| **日期** | 2026-07-11 |
| **目标** | 解决票根信息区字体在不同尺寸下留白过多或溢出的问题，实现基于容器高度的真正自适应缩放 |

## 需求描述

对票根信息区（InfoArea）进行以下调整：

1. 地点英文大写分两行显示，字号加大加粗
2. 日期格式改为 `yyyy - mm`
3. 编号格式改为 `NO.yyyymmdd`
4. 随机码长度从 5 位增加到 8 位
5. 条形码居左对齐，颜色随背景自动切换
6. **核心难点**：字号需随票根尺寸自适应缩放，保持视觉比例一致

## 分析思路

### 关于字体自适应的实现方案评估

| 方案 | 原理 | 问题 |
|------|------|------|
| 固定 `px` | `text-[28px]` | 票根放大时字号不跟随，留白过多 |
| CSS `clamp(%, %, %)` | `fontSize: 'max(10px, 6%)'` | **误以为 `%` 是容器高度百分比** |
| **JS + ResizeObserver** | 读取 `clientHeight` 计算 | **真正基于容器高度，正确方案** |

**关键发现**：CSS `font-size: 10%` 的百分比参照的是**父元素的字体大小**（继承自根元素约 16px），不是容器高度。因此 `10%` 实际只有约 1.6px，被 `max(10px, ...)` 限制在 10px，导致无论怎么调百分比都无效。

## 实现过程

### 1. 引入 pinyin-pro 进行中文地名拼音转换

```bash
npm install pinyin-pro
```

中文地点（如"杭州"）自动转为拼音大写（`HANGZHOU`），再按长度智能分割为两行（`HANG` / `ZHOU`）。

### 2. 实现 ResizeObserver 动态字体计算

```vue
<template>
  <div
    ref="infoAreaRef"
    class="flex flex-col justify-center h-full px-[4%] py-[3%]"
    :style="{ color: textColor, fontSize: baseFontSize + 'px' }"
  >
    <!-- 子元素使用 em 单位 -->
    <div style="font-size: 2.0em;">...</div>
  </div>
</template>
```

```typescript
const updateFontSize = () => {
  if (!infoAreaRef.value) return
  const height = infoAreaRef.value.clientHeight
  // 基准字号 = 容器高度的 6%，最小 10px
  baseFontSize.value = Math.max(10, Math.round(height * 0.06))
}

onMounted(() => {
  updateFontSize()
  resizeObserver = new ResizeObserver(() => updateFontSize())
  resizeObserver.observe(infoAreaRef.value)
})
```

### 3. 最终比例参数

| 元素 | 基准倍数 | 占容器高度比例 |
|------|----------|---------------|
| 地点（两行） | `2.0em` | 约 24% |
| 日期 | `1.15em` | 约 6.9% |
| 编号 | `0.95em` | 约 5.7% |
| 随机码 | `0.95em` | 约 5.7% |
| 条形码 | `mt-[0.5em]` | - |
| 上下留白 | `py-[3%]` | 约 6% |

## 遇到的问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 调整 CSS 百分比无效果 | 误解 `font-size: 10%` 为容器高度百分比，实际是父元素字体大小的 10% | 改用 JS 读取 `clientHeight` 计算 |
| 字号过大导致条形码溢出 | 基准 7.5% + 地点 2.5em 总高度超过容器 | 降至基准 6% + 地点 2.0em，增加上下内边距 |
| 字号过小导致留白过多 | 基准 5.5% 比例不足 | 逐步上调至 6%，配合 2.0em 地点倍数 |

## 关键教训

### CSS `font-size` 百分比参照基准

CSS `font-size: X%` 的参照物是**父元素的字体大小**，不是容器高度、宽度或其他属性。要实现基于容器尺寸的字体缩放，必须使用：
- JS 读取容器尺寸后动态计算
- 或 CSS 容器查询（Container Queries，浏览器支持度有限）

### 验证方法

本次反复修改无效的根本原因是**没有验证字体实际像素值**。后续应通过浏览器 DevTools 直接检查计算后的 `font-size` 值，而不是仅凭视觉判断。
