# 20260716-2111-颜色提取算法优化与冷暖平衡调优

## 背景

用户上传了一张夕阳照片（海边木栈道），发现自动提取的色板中完全没有夕阳的橙黄色调，只有灰蓝色。经过分析，原始算法存在以下问题：

1. **强制降饱和**：所有颜色被限制在40%饱和度，高饱和的夕阳色被严重削弱
2. **按像素频率排序**：夕阳色只占照片小面积，被大面积蓝天淹没
3. **采样分辨率低**：100×100像素，细节丢失
4. **量化步长粗糙**：16步长，颜色层次不足

## 优化过程

### 第一轮改进：基础算法升级

- 采样分辨率从100×100提升到150×150，保持原始宽高比
- 量化步长从16降低到8，保留更多色彩层次
- 排序逻辑从纯像素频率升级为**视觉显著性分数**（频率+饱和度+亮度）
- 修复了量化值溢出bug（`Math.round(253/8)*8=256`超出255范围）

**结果**：色板出现暖色，但暖色过多（5个暖色+1个蓝色），蓝天图的蓝色被压制。

### 第二轮改进：条件触发暖色保护

- 暖色保护不再无条件启用
- 只有当暖色像素占比超过8%时才启用
- 蓝天图（暖色占比<8%）不会强制添加暖色

**结果**：蓝天图恢复正常，但夕阳图的暖色仍然过多。

### 第三轮改进：保护机制数量限制

| 保护类型 | 数量限制 | 触发条件 |
|----------|----------|----------|
| 高饱和色 | 最多2个 | 始终启用 |
| 暖色调 | 最多1个 | 暖色像素占比>8% |
| 冷色调 | 最多1个 | 冷色像素占比>5% |
| 自然排序 | 剩余名额 | 从候选色中补充 |

**结果**：色板更平衡，但冷色仍然偏少。

### 第四轮改进：冷暖平衡与色相多样性

1. **冷色保护增加到2个**，降低触发阈值（饱和度>15，占比>3%）
2. **视觉分数加入色相差异奖励**：与已选颜色色相差异越大，分数越高
3. **保护机制预留自然排序空间**：各维度上限总和<色板容量

**最终色板效果**（夕阳图）：
- 橙色 rgb(255, 168, 64)
- 浅橙黄 rgb(255, 208, 112)
- **蓝色 rgb(80, 144, 216)** ← 新增冷色
- 深橙 rgb(255, 128, 40)
- 亮黄 rgb(255, 248, 64)

## 核心设计原则

1. **人工干预给方向，不垄断名额**：保护机制只占用部分名额，剩余留给算法自然选择
2. **条件触发，避免一刀切**：暖色/冷色保护只在图片中确实存在该类颜色时启用
3. **正交化设计**：高饱和色、暖色、冷色三个维度独立计算，避免语义重叠
4. **色相多样性奖励**：已选颜色越多，新颜色的色相差异奖励越高，促进色板丰富度
